# Информация о проекте

**pz2-grpc** — учебный gRPC-сервис `StudentService` на Go с контрактом в Protocol Buffers.
Сервер хранит студентов в памяти, клиент вызывает RPC-методы по сети.

## Цели занятия

- Понять назначение gRPC и отличие от HTTP JSON API.
- Описать контракт в `.proto` и сгенерировать Go-код.
- Реализовать gRPC-сервер и клиент на Go.
- Передавать структурированные данные через protobuf.
- Обрабатывать gRPC-ошибки (коды статуса).

## ВАЖНОЕ ПРИМЕЧАНИЕ

Сервер слушает порт **50051**.

**Почему 50051:** это распространённый порт в официальных примерах gRPC (Hello World и др.). gRPC — не HTTP, он не обязан быть на 8080. Мы взяли привычный учебный порт и не пересекаемся с HTTP-практиками (8081, 8082, 8087…).

Для учёбы используется соединение **без TLS** (insecure).
Перед клиентом должен быть запущен сервер.

## Запуск

```powershell
cd pz2-grpc
.\start-server.ps1    # окно 1
.\run-client.ps1      # окно 2
```

Генерация после изменения `.proto`:

```powershell
.\generate.ps1
```

## Тесты

В отдельном окне после запущенного сервера:

```powershell
cd pz2-grpc
.\run-client.ps1
```

(или `go run ./cmd/client` — см. «Запуск без PowerShell».)

## Запуск без PowerShell

Из каталога `pz2-grpc`. Сначала сервер, затем клиент (в другом терминале).

**Терминал 1 — сервер (порт 50051):**

```text
go run ./cmd/server
```

**Терминал 2 — клиент:**

```text
go run ./cmd/client
```

Генерация кода после правки `.proto` (нужен `protoc` и плагины Go):

```text
protoc --go_out=. --go-grpc_out=. proto/student.proto
```

| Метод | Описание |

| `Ping` | проверка, что сервер жив |

## Дополнительные задания (выполнено)

### ListStudents

**Как работает:** клиент вызывает `ListStudents` с пустым сообщением `Empty`. Сервер возвращает `ListStudentsResponse` со срезом всех записей из map в памяти.

### CreateStudent

**Как работает:** клиент передаёт ФИО, группу, email и специализацию. Сервер проверяет обязательные поля, уникальность email, присваивает новый `id` и сохраняет в map. Ответ — `GetStudentResponse` с созданным студентом.

### Поле specialization

**Как работает:** в сообщении `Student` добавлено поле `specialization`. После изменения `.proto` нужен `.\generate.ps1` — Go-структуры обновляются автоматически, поле доступно в API и в тестовых данных.

## Примеры запросов и ответов

Клиент: `go run ./cmd/client` (сервер на порту **50051**). Ниже — смысл ответов в JSON-виде (по факту идёт protobuf).

### Ping

Запрос: `Ping(message: "hello grpc")`
Ответ: `{"message":"Server received: hello grpc"}`

### GetStudentByID id=1

Ответ:

```json
{
  "student": {
    "id": 1,
    "full_name": "Иванов Иван Иванович",
    "group": "ИТТ-01-25",
    "email": "ivanov@example.com",
    "specialization": "Программная инженерия"
  }
}
```

### GetStudentByID id=999

Ошибка gRPC: код **`NotFound`**, сообщение вроде `student not found` (не HTTP 404).

### ListStudents

Ответ: массив из **3** студентов (id 1–3) в поле `students`.

### CreateStudent

Запрос: ФИО, группа, email, specialization.
Ответ: созданный студент с новым `id` (клиент в тесте создаёт **Козлова**, обычно `id=4`).

## gRPC-ошибки

| Код | Когда |
|-----|-------|
| `InvalidArgument` | id ≤ 0 или пустые поля при создании |
| `NotFound` | студент не найден |
| `AlreadyExists` | email уже занят |
